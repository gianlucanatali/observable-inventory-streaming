# Storefront

Fictional outdoor/trail retailer UrbanStreet (Vite + React frontend, Flask backend).

`backend/app/products.json` is the storefront's own display catalogue for P0001..P0200. Each product id is a SKU (one model in one colour and size); the SKUs are grouped into 21 models (`model_id`, `variant_rank`). Each model has a `kind` (from its photo type, for example `trail running shoe`) and `waterproof` (GTX in the name, or a photo type described as waterproof); its description's use comes from a family shared by models of the same kind. The offer worker ranks alternatives by these. The grid shows one card per model; a product page shows colour swatches and size buttons, and every variant keeps its own URL (`#/product/P0042`). `GET /api/products/<id>` adds the model's `variants`. Sibling sizes' availability is read with the same per-SKU API, once on arrival and then every 10 s; only a confirmed out-of-stock size is disabled.

The file is generated by `python3 storefront/scripts/export_products.py` (run from `overlay/`) and checked in. The inventory API generator is only read (P0042 must match it), never changed. P0042 (Alpenpace Trailrunner GTX, Forest green, EU 42) and the EU 42 offer pool for it (P0160, P0061, P0146) keep their earlier facts, so the offer candidates are the same; the script fails if that pool changes.
