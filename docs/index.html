Observable inventory streaming with Confluent and Datadog

Stream stock changes from the stores to the online shop. Then use Datadog to find and fix a slow release.

  • Start the workshop
  • View on GitHub

The same stock number online and in the stores

Five store databases, left unchanged, send every stock change to one copy that the online shop reads. The online shop shows how many items the stores really have.

Lab 1: one online number

Ship a release safely

A new release is slow. It goes to only 10% of shoppers first (a canary), and a check stops it there. Datadog traces show why it is slow, and you roll out the fix the same way.

Lab 3: the incident

Restock orders and offers

The same stream of stock changes also creates restock orders and offers for shoppers. Each one has a safe default.

Lab 5: restock that learns

Everything in Datadog

One place for traces, data streams, freshness (how long a change takes to reach the online shop), monitors and cost, across the stores, Confluent Cloud and AWS.

Lab 7: Datadog on top

What you build

PostgreSQL and Debezium run in the stores and Confluent Cloud sits in the middle. The online shop reads from Redis on AWS, and Datadog monitors every part.
